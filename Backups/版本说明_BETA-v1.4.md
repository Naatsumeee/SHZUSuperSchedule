## 技术要点（这一版踩到的两个硬骨头）

### 1. 后台抓取必须由 WebView 自己发请求

`HttpURLConnection` 复用 `CookieManager` 的 Cookie **拿不到 `JSESSIONID`**
（教务是多机负载均衡，WebView 的 Cookie 里只有 `SERVERID` / `bzb_njw` / `jsxsd` 三项），
请求回来是 164 字节的无 title 空壳页。改用**内嵌 WebView 里跑 JS `fetch`** 后，
Cookie / UA / Referer 全由浏览器处理，问题消失。

另外教务会话极脆：**连续快速请求会被判定爬虫并踢掉会话**
（实测第 1 个请求正常、第 2 个起全空壳），所以 `JwglQueryFetcher.STEP_DELAY_MS = 1200`
不是可选项。

### 2. 等级考试成绩表的「双层表头写进了数据区」

教务这张表的 thead 只有一行，父列用 `colspan` 铺开（`1+1+4+3+1+1 = 11` 列），
真正的子列名（笔试 / 机试 / 总成绩 …）**单独占了 `<tbody>` 的第一行**，于是被当成数据。

后果有两个，都是用户实际看到的：

- 那行的前两列是空的，第一个非空单元格是「笔试」→ 界面上凭空多出一条
  **标题为「笔试」、内容全是「机试 / 总成绩」的空卡片**；
- 4 列「分数类成绩」拿不到子名、全部同名 → 无法分辨哪一列才有分数，
  只能退化成"取第一个非空值"，于是挑中了教务用来表示"这项没成绩"的 **`0`**，
  真正有分数的子列反而被丢掉。

解法是**把那一行当第二层表头用**（`JwglQueryParser.repairStrayHeader`）：
按列号把子名拼到父名后面（`分数类成绩 / 总成绩`），再把它从数据里剔除；
界面据此优先取「总成绩」，并跳过 `0` / `-` / `无` 这类占位值。
**改解析器救不了老存档**，所以 `QueryStore.sanitize` 在**读取**时也做同一件事 ——
用户不刷新、不重抓，打开 App 就能看到正确结果。

### 3. 构建脚本合并

原先 `tools/` 下躺着 27 个**逐字节相同**的 `build_km_v*.ps1`（都是 `sed 's/v151/v152/g'` 派生出来的），
改一处环境变量要改 27 遍。已合并为带版本参数的单一入口 `tools/build_km.ps1`：

```bash
powershell -ExecutionPolicy Bypass -File tools/build_km.ps1 -Version 165      # Release
powershell -ExecutionPolicy Bypass -File tools/build_km.ps1 -Variant Debug    # Debug
```

同时修掉两个静默失败：`Tee-Object` 会把日志写成 UTF-16（`grep` 永远匹配不到
`BUILD SUCCESSFUL`），以及脚本里的 `exit` 会杀掉宿主进程、输出全丢。
失效的 Flutter 时代脚本 `build_apk.ps1` 已删除。

### v166 修订详情

真机日志对照时发现：等级考试表的表头明细仍然打印
`分数类成绩 ×4 | 等级类成绩 ×3` —— 四列全同名，说明**补名根本没生效**。

根因是 `repairStrayHeader` 写好后只接进了 `JwglQueryParser.readTable`（**新抓取**路径），
而 `QueryStore.sanitize`（**读老存档**路径）还是原来的 `filterNot { isStrayHeaderRow }`
写法 —— 只剔除、不补名。于是「老存档不用刷新也能看到正确列名」这条承诺落空。

修法：`sanitize` 改为「先滤占位行 → 再 `repairStrayHeader(headers, kept)`」，
并新增日志 `存档清理：补回 N 张表丢失的子列名` 便于对照。

教训：**新增一个"既有剔除又有改造"的函数时，两个调用点都要接上**。
只写 `isStrayHeaderRow` 的判据、却在另一处用旧写法重写一遍逻辑，是最容易漏的那种。
