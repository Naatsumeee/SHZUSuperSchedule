# 交接提示词

把这个文件夹交给**任意另一个 Agent** 时，把下面这段话贴给它即可。
完整版见工程根目录 **[../../PROJECT_PROMPT.md](../../PROJECT_PROMPT.md)**（本文件同源，只是摘要）。

---

## 可直接粘贴的 Prompt

````text
这是「石大超级课表」的工程项目，一个面向石河子大学的 Android 课表 App。
请先阅读工程根目录下的 PROJECT_PROMPT.md 和 README.md，它们包含完整的技术栈、
构建方式和几条会让编译直接失败的红线。

要点速览：
- 唯一正式工程是 shzu_class_km/（Kotlin + Jetpack Compose + MiuiX 0.9.3），
  其余目录（Backups/ History/ docs/ tools/ reference/）都不参与构建。
- 构建：powershell -ExecutionPolicy Bypass -File tools\build_km_v145.ps1
  看结果必须用：cat km_build_v145.txt | tr -d '\000' | sed 's/\r//' | grep -E "^e: |BUILD"
  （PowerShell Tee-Object 写出的是 UTF-16，直接 grep 会误判）
- 依赖版本强绑定，不要升级 AGP / Gradle / Kotlin / Compose / MiuiX 任何一个。
- Kotlin 字符串模板里 "$变量()" 或 "$变量中文" 会编译失败，必须写 "${变量}"。
- 改完代码一定要实际构建验证，不要只写代码。

历史决策记录都在 History/ 目录（不参与构建）：
- History/memory/ 是核心，技术决策的来龙去脉都在里面；
- History/prompts/ 记录了需求是怎么一步步提出来的；
- History/legacy/ 是已废弃的 Flutter 版源码。
每个 release 版本的 APK 和改动声明在 Backups/。

现在请告诉我你已经理解了项目结构，然后等待我的具体任务指令。
````

---

## 为什么要写这一段

换 Agent 时最大的风险不是「看不懂代码」，而是**踩已经踩过的坑**：

- 把 `Tee-Object` 的 UTF-16 日志当纯文本 grep，误判构建失败；
- 升了一下 MiuiX 或 AGP，连锁崩掉一整套依赖；
- 写了 `"$sections小节"` 然后对着编译错误发呆；
- 不知道 `History/` 里有完整决策记录，重新排查一遍已经解决过的问题。

上面这段话把这几条前置堵住了。

## 补一句给 Agent 的行为约束

如果这个 Agent 要直接改代码，建议再补：

````text
用户的协作偏好：
- 每次改完必须编译验证。
- 用户说自己会测试时，交付并停止，不要自作主张继续改。
- 用户反馈通常非常具体，按字面实现，不要自己重新解释需求。
````
