# 桌面小组件

5 个 provider：自适应 `ScheduleWidgetProvider` + Small / Wide / Tall / Big
（2×2 / 4×2 / 2×4 / 4×4，在 `widget/FixedSizeWidgetProviders.kt`）。

## 🚨 最容易踩的坑：RemoteViews 白名单

布局里**禁用 `<View>`** —— `android.view.View` **不在 RemoteViews 白名单里**。
色条 / 分隔线要用 `ImageView` 代替。

**为什么这个坑特别难查**：

- 桌面膨胀时确实会抛异常，但**被 MIUI 静默吞掉**；
- 表现为永久灰色的「载入窗口小部件时出现问题」；
- 而 `previewLayout` 走的是普通渲染路径，**看起来完全正常**。

⇒ 现象和原因完全对不上，极具迷惑性。

## 排查方法

```bash
adb logcat | grep "flutter :"      # hyper_launcher_app 是 Flutter 应用
```

关键行：

- `[AppWidgetHostView] INFLATE path`
- `[AppWidgetHostView] _buildWithLayoutParams`

**判据：有 `INFLATE path` 但没有 `_buildWithLayoutParams` = 膨胀被吞 → 查白名单。**

Provider 推送前可以自检：

```kotlin
rv.apply(context, FrameLayout(context))   // 捕获异常打日志
```

## 其他要点

- **尺寸档位靠多个 `<receiver>`**：MIUI 的选择器把每个 receiver 当成一个条目，
  每个配独立的 xml info。
- `initialLayout` 指向**加载态**布局（小米官方规范），`previewLayout` 指向正式布局。
- **卡片要填满格子**：根布局 `match_parent`，行高按
  `OPTION_APPWIDGET_MIN/MAX_HEIGHT` 的真实 dp 扣除固定开销后均分（`setMinimumHeight`），
  不要用 `wrap_content + minHeight`。
- **行控件 id 不能重复**（v1.3.1 修过：重复会导致显示错乱）。
- shell 无法广播 `APPWIDGET_UPDATE`（SecurityException）；
  触发更新用 `monkey` 拉起 app 或重启桌面。
