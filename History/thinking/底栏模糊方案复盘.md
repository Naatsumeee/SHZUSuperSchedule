# 底栏模糊方案复盘

**目标**：底栏毛玻璃 = 模糊的确实是**底栏背后**的页面内容。
**结果**：成功。性能约 +4~5ms/帧，60Hz 无卡顿。
**过程**：绕了两次弯路，两个根因各自独立、必须同时解决。

---

## 最终方案：三层图层

```
contentLayer  ← 整页内容
   ↓ 切片
sliceLayer    ← 尺寸 = 底栏尺寸，内容 = 整页图层按偏移平移后的那一块
   ↓ 分 5 段、每段挂不同半径的 RenderEffect
band[0..4]    ← 合成到底栏画布，半径自下而上递减
```

```kotlin
// 1) 录整页（drawContent() 必须是第一个绘制调用）
contentLayer.record(size = IntSize(width, height)) { drawContent() }

// 2) 切片：先切再模糊，内容自然落在 sliceLayer 自己的边界内
val off = state.contentTopY - state.barTopY + tuning.extraOffset
state.sliceLayer.record(size = IntSize(barW, barH)) {
    translate(top = off) { drawLayer(state.contentLayer) }
}

// 3) 分段模糊
graphicsLayer { renderEffect = BlurEffect(r, r, TileMode.Clamp) }
drawLayer(state.sliceLayer)
```

---

## 根因 1：`GraphicsLayer.record` 的重载选错

有两个同名 `record`：

| 签名 | 行为 |
|------|------|
| `GraphicsLayer.record(density, layoutDirection, size, block)` | ❌ **另建一个 `CanvasDrawScope`**，`drawContent()` 画到屏幕上 |
| `DrawScope.record(size) { ... }`（成员扩展） | ✅ 把**本节点的 canvas** 换成图层画布 |

必须用后者。

**定位手段**：反编译 `LayoutNodeDrawScope` 的字节码，里面有自描述的错误字符串
说明了 record 的语义。当文档说不清楚时，反编译看实现是可靠办法。

---

## 根因 2（决定性）：带 `renderEffect` 的节点会把内容裁在自身边界内

带 `renderEffect`（**含 `Modifier.blur`**）的节点会被渲染进一张
**按节点自身尺寸分配**的离屏缓冲，**边界外的内容整块丢弃**（哪怕 `clip = false`）。

当时的写法：在 315px 高的底栏 Canvas 里 `translate(top = -2885)` 把整页图层拖进来
→ 内容全在边界外 → **一像素不画** → 底栏退回「透明栏直接透出实时页面」。

**这就是"看起来完全没模糊"的真正原因。**

附带结论：`Modifier.blur` 内部其实是 `clip = true`
（`BlurredEdgeTreatment.Rectangle` 等价 `RectangleShape`），
所以要模糊"栏外内容"必须改用**显式 `RenderEffect`**（`graphicsLayer` 默认 `clip = false`）。

---

## 渐变（用户反馈「模糊过于生硬」之后加的）

- 半径自下而上递减：
  `radius = BLUR_MAX_DP * (BAND_TOP_RATIO + (1 - BAND_TOP_RATIO) * i / (n - 1))`
  实测 44dp 起点 → **165 / 134 / 103 / 72 / 41 px**（density 3.75）
- 每层用 `CompositingStrategy.Offscreen` + `drawRect(verticalGradient, blendMode = DstIn)` 淡出，
  淡出跨度取 **1.6 个档位**使相邻层交叉 → 消除「一级一级跳」。最底层整条不透明垫底。
- 底色改为**顶边完全透明** → 0.45 → 0.65 的纵向渐变；高光也用渐变（1px 实线太生硬）。
- 实测顶边跨界差仅 **1.012**（栏上方基线差 0.000），几乎无硬边。

## 验证方法（可复用，且很容易自欺）

### 决定性信号

同一滚动位置下对比 `blurDp = 0` vs `44`：

| 指标 | 不模糊 | 模糊 |
|------|--------|------|
| 底栏 `dx` | 2.635 | **0.754** |
| 底栏 `dy` | 3.440 | **1.227** |
| 洋红诊断边框行 | mean 170.00 / std 0.00 | mean 201.6 / min 180 / max 203（被糊开） |

### 🚨 最大的自欺坑：跨运行对比

`adb input swipe` 的滚动落点**每次可能不同**。实测两次运行「栏上方区域」的
mean 分别是 244.37 和 234.66 —— 内容都变了，统计数字当然不同，
**这完全说明不了模糊有没有生效**。

正确做法二选一：
1. 先确认两次运行的页面统计一致，再比；
2. **用同一张图内部自比**：「栏上方区域」vs「栏内区域」。

### 其他

- **课表页不需要纵向滚动**，swipe 不产生重绘。测滚动帧率要用**设置页**。
- 页面滑到底后 `input swipe` 不产生新帧（`gfxinfo` 只有 2 帧）→ 必须重启 App 复位。

## 性能

设置页 6 次 swipe：

| | 帧数 | Janky | p95 | p99 |
|---|---|---|---|---|
| 模糊开 | 494 | **0** | 10ms | 12ms |
| 直通 | 512 | 0 | 5ms | 6ms |

⇒ 约 **+4~5ms/帧**，60Hz 下无卡顿，可接受。
