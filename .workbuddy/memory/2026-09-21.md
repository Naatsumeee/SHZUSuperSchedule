# 2026-09-21 工作日志

## 新增「查询」页（分支 `教务查询接入`）

### 需求

在现有三个主页面之外再加一个页面，**排在周视图之后**，提供三个查询入口：

| 入口 | 教务菜单路径 |
|------|--------------|
| 考试安排 | 考试报名 → 我的考试 → 考试安排查询 |
| 课程成绩 | 学籍成绩 → 我的成绩 → 课程成绩查询 |
| 等级考试成绩 | 学籍成绩 → 我的成绩 → 等级考试成绩 |

教务地址 `jwgl.shzu.edu.cn`。要求与现有页面的导航、样式保持一致。

### 关键设计决策

**1. 数据获取走 WebView 抓 HTML，而不是后端 POST**

现有的「刷新可读学期」是后端静默抓取（Cookie + HttpURLConnection）。
但这次不能照搬，原因两条：
- 三类查询的**接口名与参数各校不同**，写死容易失效；
- **考试安排查询需要用户在页面里自选学年学期**，表单参数无法预先确定。

走 WebView 的好处：无论教务怎么改，只要能看见表格就能抓。

**2. 不做逐字段建模，只做「通用表格解析」**

三个页面的表结构完全不同，学校升级一次就可能全变。
所以 `JwglQueryParser` 只做一件事：把页面上的结果表读成「表头 + 行」。
找表优先级：`#dataList` / `#tabList` / `.tbllist` 等常见 id → 兜底取**数据行最多**的表。
只要教务还在用表格展示数据，改版也不会解析失败。

**3. URL 是「候选」而不是「唯一」**

教务各校查询路径差异大，`QueryKind.paths` 存候选列表，只取第一个当「直达」按钮的目标。
UI 上明确写着菜单路径，**打不开就让用户在网页里手动点菜单**，抓取逻辑完全不依赖具体地址。
这样即使我猜的 URL 全错，功能依然可用。

### 踩到的坑

- **`SubPageTopBar` 原本是 SettingsPage 的 `private`**，查询页要用同一套，
  已提升为 `PageHeader.kt` 里的 `internal` 公共组件。
- **加 tab 会让索引整体后移**：`selectedTab` 由 0/1/2 变成 0/1/2/3，
  `MainScaffold` 的 `when (selectedTab)` 和 `BlurredBottomBar` 的 `NavigationBarItem`
  必须同步改，漏一处就串页。
- 查询结果用**覆盖层**呈现而不是替换 WebView —— 换掉会让 AndroidView 被移出组合导致
  WebView 销毁、页面状态丢失。覆盖层方案下 WebView 始终在底层活着。
- WebView 的加载进度要**显式回调出来**（`onProgressChanged`），
  否则进度条永远不动（我第一版就漏了这个）。
