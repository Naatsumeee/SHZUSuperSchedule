## 小组件「载入窗口小部件时出现问题」—— 真正根因已修复 ✅

所以预览完美、放桌面就坏。曾误判为 initialLayout/wrap_content/缓存问题。

## 1. 底栏真实背景高斯模糊（关键，绕了两次弯路）

用户两轮反馈：「透明效果仍不明显」→「过于透了，且没有模糊效果」。
**根因有两个，缺一不可**：

1. **只有半透明平铺，根本没有模糊**。Compose 没有现成的「背景模糊」修饰符；
   `RenderEffect.createBlurEffect` 只能作用于**自己这一层**的绘制内容，无法糊到别的层。
2. **MiuiX `NavigationBar` 内部硬编码不透明底色**：
   `NavigationBar(color: Color = MiuixTheme.colorScheme.surface)` 内部直接 `.background(color)`，
   把底下辛苦做的磨砂层整个盖住。必须传 `color = Color.Transparent` **且** `showDivider = false`。

**解法 = 两层 GraphicsLayer「拷贝再模糊」法**（`ui/BlurBar.kt`）：

- contentLayer：`Modifier.recordBarBackdrop(state)` → `drawWithContent { graphicsLayer.record { this@drawWithContent.drawContent() }; drawLayer(graphicsLayer) }`
  录制**页面内容本体**（正常清晰显示）。
- onGloballyPositioned 里存 `contentTopY` / `barTopY`（`positionInWindow().y`），用于算相对偏移。
- barLayer（在底栏容器的 `drawBehind` 里）：
  `barLayer.renderEffect = BlurEffect(24f, 24f, TileMode.Clamp)`，
  然后 `barLayer.record(size) { translate(top = -(barTopY - contentTopY)) { drawLayer(contentLayer) } }`，
  最后 `drawLayer(barLayer)` —— 模糊的是**内容层的拷贝**，不是内容本身。
- 再叠 `drawRect(Brush.verticalGradient(0.78f→0.93f))` + 顶部 1px 高光。
- `BlurEffect` 用 `remember(density)` 缓存，别每帧新建。
- 关键 API（CMP 1.11.1，已 javap 核对 aar）：
  `androidx.compose.ui.graphics.rememberGraphicsLayer()`（在 `GraphicsLayerScopeKt`）、
  `GraphicsLayer.record(density, layoutDirection, IntSize, DrawScope.() -> Unit)` / `renderEffect` / `drawLayer()`；
  `androidx.compose.ui.graphics.BlurEffect(x, y, TileMode)`。
- **绘制顺序成立的前提**：MiuiX `Scaffold.kt` 里 `bodyContentPlaceable.place(0,0)`
  **先于** `bottomBarPlaceable.place(...)` → 底栏绘制时 contentLayer 已是本帧内容，**零帧延迟**。
- 降级：`RenderEffect` 需 API 31+，`blurSupported()` 判断，低版本只留半透明底色。

## 1. 🔴 模糊「一像素都不画」的两个根因（决定性实验定位）

用户反馈「依然没有模糊效果」。做了**像素级对照实验**（dbg=1 偏移 0 vs dbg=2 真实偏移）
→ 两张截图**逐像素完全相同（差异 0 像素）** ⇒ 图层内容不随偏移变化 ⇒ 内容压根没进图层。

**根因 A：`record` 用错了重载。**
- ❌ `GraphicsLayer.record(density, layoutDirection, size, block)`（GraphicsLayer 的**成员**函数）——
  它另建一个 `CanvasDrawScope`，block 里的 `drawContent()` 仍画到**屏幕**，图层里只剩 block 中
  直接 `drawRect` 的东西。
- ✅ `layer.record(size = IntSize(w, h)) { … }`（**DrawScope 的成员扩展**，在 `drawWithContent` 里调）——
  实现会临时把本节点 `DrawContext.canvas` 换成图层画布，`drawContent()` 才真的画进图层。
- 证据：反编译 `LayoutNodeDrawScope`（`javap -p -c`，见上文 `.jsrc` / `lnds.txt`）字节码里有自描述字符串
  `"Attempting to drawContent for a null node… make sure you are using the GraphicsLayer#record function
  within DrawScope, instead of the member function on GraphicsLayer."`
  修好后 dbg1 vs dbg2 差异像素 **14885 个**（mean|diff| 5.79），证明内容进图层了。

**根因 B：带 `renderEffect` 的节点会把内容裁在**自身边界内。
改对 record 后依然不糊（dbg3 `Modifier.blur` / dbg4 裸 `RenderEffect` 都没效果）。
真因：设了 `RenderEffect` 后节点会被渲进一张**按节点尺寸分配**的离屏缓冲，**边界外内容整块丢弃**
（`clip = false` 也救不了；`Modifier.blur` 更是内部自带 `clip = true`）。
band 循环把图层 `translate(top = -2885)` 拖进 315px 高的底栏画布 → 全在边界外 → 一像素不画，
底栏只是"透明栏透出实时页面"。

**最终解法 = 三层图层**（`ui/BlurBar.kt` 已重写）：
1. `contentLayer`：整页内容（`record(size) { drawContent() }`，`drawContent()` 必须是第一个绘制调用）；
2. `sliceLayer`：**尺寸 = 底栏尺寸**，内容 = `translate(top = contentTopY - barTopY) { drawLayer(contentLayer) }`
   —— 先切好再模糊，内容自然落在自己的边界内；
3. 5 个 band `Canvas`：`graphicsLayer { renderEffect = BlurEffect(r, r, TileMode.Clamp) }` 后 `drawLayer(sliceLayer)`。

⇒ 仓库必须由用户在网页创建（或换 classic token），我只能 push。

### 🔴 卡点 2：git 认证方式与 token 写权限

- `git -c http.extraheader="AUTHORIZATION: Bearer <TK>" push` → **`remote: invalid credentials`**。
  GitHub 的 git-over-HTTPS **不吃 Bearer 头**，要按 Basic 走：
  `git push https://<user>:<TOKEN>@github.com/<user>/<repo>.git main`
  （一次性 URL 不会把 token 写进 `.git/config`）
- 换 Basic 后认证通过，但报 `Permission to ... denied to ... (403)`。
  诊断：
  - `GET /repos/{r}/contents/` → 404 `This repository is empty`（**能读**，不是权限问题）
  - `POST /repos/{r}/issues` → **403**（**没有写权限**）
  ⇒ fine-grained token 缺 **Contents: Read and write**（且仓库可能不在其授权范围内）。
  用户需在 https://github.com/settings/personal-access-tokens 编辑该 token，
  或改用 classic token（`ghp_`）勾 `repo`。

### 推送方式（token 不落盘）

```bash
git remote add origin https://github.com/Naatsumeee/SHZUSuperSchedule.git

```
用 `http.extraheader` 而不是把 token 拼进 URL，避免写进 `.git/config`。
